# Backend REST API Documentation

Base URL (local): `http://127.0.0.1:8002` (run with
`uvicorn backend.main:app --port 8002`)

Interactive docs are also auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc` once the server is running.

## Candidate Management

### `POST /candidates`
Create a candidate.

Request body:
```json
{
  "full_name": "Ananya Rao",
  "email": "ananya.rao@example.com",
  "phone": "9840000001",
  "location": "Chennai",
  "skills": ["python", "fastapi", "postgresql"],
  "years_experience": 3.5,
  "current_title": "Backend Developer",
  "resume_summary": "..."
}
```
- `201` -> the created candidate, with `id`.
- `422` -> validation error (e.g. missing `full_name`, invalid email).
- `409` -> a candidate with that email already exists.

### `GET /candidates/{candidate_id}`
- `200` -> candidate object.
- `404` -> not found.

### `GET /candidates?skill=python&limit=50`
List/search candidates, optionally filtered to those who have a given skill.

## Job Management

### `POST /jobs`
Create a job requisition.
```json
{
  "title": "Python Developer",
  "department": "Engineering",
  "required_skills": ["python", "fastapi", "sql"],
  "min_experience": 2.0,
  "description": "...",
  "status": "open"
}
```
- `201` -> created job.
- `422` -> validation error.

### `GET /jobs/{job_id}`
- `200` -> job object. `404` -> not found.

### `GET /jobs?status=open`
List jobs, optionally filtered by status (`open` / `closed`).

## Matching

### `POST /match`
Score and rank candidates against required skills / minimum experience —
either passed explicitly or pulled from a `job_id`.
```json
{
  "job_id": 1,
  "top_k": 5
}
```
or
```json
{
  "required_skills": ["python", "fastapi"],
  "min_experience": 2.0,
  "top_k": 5
}
```
Response: a list of `{"candidate": {...}, "score": 97.7, "score_breakdown": {...}}`,
best match first. `score_breakdown` includes `matched_skills`,
`missing_skills`, `skill_score`, and `experience_score` so every ranking is
explainable.

## Shortlists

### `GET /shortlists/{shortlist_id}`
Retrieve a previously saved, ranked shortlist (created via the
`shortlist_candidates` MCP tool — see `MCP_DOCS.md`).
- `200` -> shortlist with its ranked `items`. `404` -> not found.

## Error handling

All error responses are JSON: `{"detail": "..."}` (or a list of field
errors for `422`s). Every 5xx is logged server-side (`backend/main.py`'s
global exception handlers) without leaking internals to the caller.

## Health

### `GET /health`
`{"status": "ok"}` — for uptime checks / load balancer probes.
